# Статус: что работает, что имитация, что в плане

Таблица для README и презентации (критерий «Выступление и ответы»). Правило: **«работает» пишем, только если
сами это запустили и видели результат**. Всё остальное — «написано, не проверено», «имитация» или «план».

Обозначения: ✔ проверено · ◐ написано, не запускали в боевых условиях · ⌛ ждёт доступа · ✘ не сделано.

Последнее обновление: 2026-10-19, после сборки `main` из всех веток и доработок B2 / TL (ветка `feat/b2-tl-batch`). Заполнены строки TL, B1, B2; в разделах
ML и FE — только то, что проверили при сборке, остальное дописывают владельцы.

**Как проверены доработки B2 / TL-13.** 2026-10-19 на машине TL: стенд в Docker с `COLLECTOR_FAKE=true`, `LLM_PROVIDER=stub` (`.diagnose/verify.sh`): `make smoke` → All good; живые проверки через gateway (импорт, `matched`, исключение, XLSX, DOCX, «везде», `request_id` в логах); ruff, mypy --strict, pytest всех четырёх сервисов и typecheck + build фронта — зелёные. (вариант Б), запросы через gateway руками и `scripts/smoke.py` (`make smoke`) → `All good`. Данные —
тестовые (`COLLECTOR_FAKE=true`), ML — эвристики (`LLM_PROVIDER=stub`). Отдельно — с `COLLECTOR_FAKE=false`
без ключа VK.

## Известные ограничения (на сейчас)

- Реальные данные не получены ни с одной площадки: нет ключа VK, пробы OK / MAX не делали; OK, MAX и
  сайты отвечают 501.
- Отбор по смыслу — пока эвристики по совпадению слов (`degraded=true`), моделей нет.
- Стенд проверен только локально без Docker; `make up` и сервер не проверены.
- Регион определяет не сборщик: он отдаёт публикации без отбора по региону; связь с регионом оценивает
  поиск/ML по источнику и содержанию (в режиме «везде» правило «без привязки → отсеяно» ещё не сделано).
- `keywords` и `region_terms` сборщик игнорирует (в контракте это подсказки, не условия).
- Для OK и MAX возможен только режим «по источникам» и только при положительном результате spike.
