# Spike B1-01: как получить посты OK и MAX

Дата: 2026-10-19. Автор исследования — Claude по поручению B1. Статус: **по документации; живых запросов
к ok.ru / max.ru не было** (в моей среде нет доступа в сеть). Каждый факт ниже помечен:
✔ — прочитано в официальной документации; ◐ — одно наблюдение через инструмент чтения страниц,
не наш клиент; ? — не проверено, шаги проверки в разделе 3.

## 1. Итог по площадкам

| Площадка × режим | Способ | Что получаем | Главное ограничение | Вывод |
|---|---|---|---|---|
| VK, источники | `wall.get` | текст, дата, метрики, ссылка | нужен сервисный ключ | сделано (B1-03), ждёт ключа |
| VK, везде | `newsfeed.search` | то же | ~1000 результатов на фразу | сделано (B1-03), ждёт ключа |
| OK, источники — API | нет метода «посты группы» | — | см. 2.1 | **не основной путь** |
| OK, источники — страницы | HTML `ok.ru/group/<id>/topics` | текст, дата, id топика ◐ | анти-бот и пагинация ? | **проверить пробой** |
| OK, везде | Yandex Search API → открыть каждую ссылку | то, что на странице | покрытие неполное, платно | зависит от строки выше |
| MAX, источники — Bot API | `GET /messages?chat_id=` | текст, время, ссылка на пост, просмотры ✔ | только каналы, где бот — **админ** ✔ | годится для своих каналов, не для чужих СМИ |
| MAX, источники — веб | `max.ru/<канал>` | без логина видна только заглушка канала ◐ | постов в HTML не видно ◐ | **проверить пробой** (`__data.json`, SSR) |
| MAX, везде | Bot API поиска нет ✔ (в доке не найден); Yandex `site:max.ru` | ссылки → страницы | зависит от веб-доступа к постам | зависит от строки выше |

## 2. Что известно

### 2.1. OK API
- ✔ В списке методов нет «получить посты группы / ленту группы». Есть `group.getStatTopics`
  (топики группы за период со статистикой; нужны права `GROUP_CONTENT` и `VALUABLE_ACCESS`; «только топики,
  которые кто-то видел»), `group.getStatTopic` и `mediatopic.getByIds` (по уже известному id, право
  `VALUABLE_ACCESS`, «сессия обязательна»).
- ✔ `VALUABLE_ACCESS` выдаётся не автоматически: письмо на api-support@ok.ru с id приложения, правами и
  сценарием. Сроков в документации нет. По правилу B1-01 («одобрение > 1 дня — отбрасываем») путь через API
  основным не считаем. Нужна ли для этих методов сессия именно пользователя, страница не говорит ?.
- ◐ Страница топика группы (`ok.ru/gruppa/topic/<id>`) открылась без логина: виден текст, дата («9 мар 2016»),
  id топика в адресе; для комментариев предлагается войти. Это одна старая страница, а не лента.

### 2.2. MAX
- ✔ Bot API (`platform-api2.max.ru`, старый домен `platform-api.max.ru` закрывается; токен в заголовке
  `Authorization` без `Bearer`; нужен корневой сертификат Минцифры). Токен выдаётся при создании бота на
  business.max.ru. Требуется ли верификация юрлица, документация не говорит; заголовок статьи на Хабре
  («публиковать ботов можно только через верифицированные юрлица РФ») намекает, что нужна; текст статьи не читал ?.
- ✔ `GET /messages?chat_id=…&count=1..100`: сообщения возвращаются, «только если чат-бот в них является
  администратором»; новые первыми; 403 — нет доступа к чату. Ограничения по частоте числом не названы, есть 429.
- ✔ Объект `Message`: `timestamp` (мс), `body` (текст и вложения), `url` — публичная ссылка на пост канала,
  `stat` (просмотры, репосты; только для каналов), у постов канала нет `sender`. Точные имена полей внутри
  `body` и `stat` на странице не названы ? — уточнить по первому реальному ответу.
- ◐ `max.ru/channel_publiccha` без логина: название, id, число подписчиков, кнопки «открыть в приложении»;
  постов, дат и ссылок на посты не видно. Читал инструмент, превращающий страницу в текст, поэтому JSON внутри
  HTML мог не попасть ? (в плане B1-01 упомянут `__data.json`).

### 2.3. Yandex Search API (для режима «везде» по OK и MAX)
- ✔ Синхронный `POST https://searchapi.api.cloud.yandex.net/v2/web/search`: `query.queryText` ≤ 400 символов
  и 40 слов, `query.page` с нуля, до 250 результатов на запрос, `region`, `sortSpec`, `maxPassages` 1–5.
- ✔ Период только `WITHIN_ALL_TIME / 1_DAY / 2_WEEKS / 1_MONTH`: произвольные даты не задать, значит отбор
  по периоду делаем после открытия страницы.
- ✔ Ответ — `rawData` (XML или HTML); все поля необязательны, состав может меняться. В описании упомянуто
  время обновления документа (`modtime`), а не дата публикации ? — дату берём только со страницы поста.
- ✔ Квоты: 10 запросов/с и 10 000/час (можно поднять через поддержку). Отложенный режим: от 5 минут на
  обработку, для интерактивного поиска не подходит.
- ✔ Цена: 488 ₽ за 1000 синхронных запросов днём (366 ₽ ночью), с НДС; бесплатного лимита в документе нет ?.
- ✔ В языке запросов Яндекса есть `site:` и `url:` (справка веб-поиска); что API принимает их в `queryText`
  так же, документация API не говорит ? — проверить одним запросом.
- ? Способ авторизации в прочитанной странице не описан (там только ссылка) — смотреть раздел «Аутентификация».

## 3. Что проверить руками (у вас есть сеть, у меня нет)

Для каждого пункта 20–30 минут, не залипать. Команды — из `services/collector_service`. Пробу запускать с компьютера и, отдельно, **с сервера для демо**:
у разных IP разный анти-бот.

1. **OK, страницы.** Взять 3 публичные региональные группы (СМИ, ГИБДД, мэрия).
   `python scripts/spike_probe.py --save https://ok.ru/group/<id>/topics https://m.ok.ru/group/<id>/topics`
   Смотреть: статус, `<time>`, JSON внутри HTML, анти-бот. Затем открыть страницу вручную, пролистать вглубь и
   в DevTools → Network найти запрос подгрузки (параметры пагинации).
2. **OK, формат даты.** Выписать 5 примеров («вчера в 14:05», «9 мар»…) — от них зависит, можно ли честно
   заполнить `published_at` (без года и без дня — не заполнять).
3. **MAX, веб.** `python scripts/spike_probe.py --save https://max.ru/<канал>`; открыть в браузере с
   DevTools: есть ли в HTML/XHR сами посты, формат ссылки на отдельный пост, есть ли дата.
4. **MAX, Bot API.** Создать тестового бота и свой канал, сделать бота админом, вызвать `GET /messages`.
   Заодно выяснить, нужна ли верификация юрлица для токена.
5. **Yandex.** Один запрос `"<фраза>" site:ok.ru` и один `site:max.ru`: возвращает ли ссылки на конкретные
   посты (а не на группы), какие поля в `rawData`, как выглядит авторизация.
6. **VK.** Когда будет ключ — `scripts/record_vk_fixtures.py` (см. README сервиса).

Результаты проб (`--save` кладёт HTML в `tests/fixtures/spike/`) — сюда, в таблицу раздела 1, вместо «?».

## 4. Предварительное соответствие полей

OK — каноничная ссылка по плану B1-04: `source_external_id` = gid группы, `post_external_id` = id топика,
`url = https://ok.ru/group/{gid}/topic/{tid}`, `title` не заполнять. Откуда брать текст и дату — после п. 1–2.

MAX — `url` из поля `url` объекта `Message` (публичная ссылка на пост канала, не строим сами, пока не увидим
формат), `published_at` из `timestamp` (мс → UTC), метрики из `stat`. Стабильный id канала — `chat_id`.
Подтвердить по первому реальному ответу.

## 5. Решения для встречи с TL на H+3

1. OK: основной путь — публичные страницы, если проба п. 1 покажет текст, дату и пагинацию без капчи.
   Иначе: показываем на демо только VK и MAX, а OK честно помечаем в `note` площадки.
2. MAX: Bot API — только для каналов, где мы админы (для демо можно завести свой канал; это не «любой
   региональный источник»). Чужие каналы — только если п. 3 найдёт посты в вебе.
3. Глобальный поиск OK/MAX — только после п. 1, 3 и 5; без веб-доступа к постам Yandex вернёт ссылки,
   которые нечем проверить, а по правилу достоверности такие в подборку не попадают.
