# FE — день 2

Зона: `frontend/`. Новый дизайн «МедиаПульс» уже в коде (главная, поиск, подборка, источники,
история, тёмная тема). Критерии: UX 5 сценариев (по 2), общий UX/UI (5), демонстрация (5).

Маршруты теперь: `/` — главная, `/search` — новый поиск, `/search/:id` — подборка, `/history`,
`/sources`. Регион — плашка «Красноярский край» в шапке (поповер с правилом), состояние площадок — внизу
меню. «Свежее» из макета не сделано: на бэкенде нет ленты последних публикаций — в меню вместо него
«История».

### [ ] FE-13 · P0 · недочёты нового дизайна
**Цель.** Общий UX/UI (5): одинаковые действия и состояния выглядят одинаково.

**Сделать.** Собрать список с командой после прогона (TL видел «пару мелких недочётов») и закрыть.
Уже известно:
1. Тексты причин у целей («Где искали», баннер «Не удалось обработать») — длинные технические строки;
   после B1-13 будут короткие, но вёрстка должна держать 2 строки и `…` с полным текстом в подсказке.
2. Плашка «Уточните регион…» в тёмной теме — слишком тяжёлая оранжевая; привести к стилю заметок
   (жёлтая полоска слева, как у баннера partial).
3. Логотип MAX, когда площадка недоступна, — серый квадрат без пояснения: в подсказке — причина из
   `/platforms`.
4. Проверить подборку на 200+ результатах: «Показать ещё», липкая полоса параметров, массовое
   исключение — не прыгает, не перекрывает шапку.
5. Светлая и тёмная тема на проекторе: контраст подписей `--mp-faint`.

**DoD.** Список закрыт, скриншоты «до/после» у UI-11; `npm run typecheck && npm run build` зелёные.

### [ ] FE-14 · P0 · состояния «Везде», очереди и долгого поиска
**Цель.** Сценарии 3 и 5: пользователь понимает, где поиск выполнен, где нет, и что система работает.

**Сделать.**
1. Режим «Везде», если у площадки `global_mode=false`: у логотипа в форме — пометка «только ваши
   источники» и подсказка; в «Где искали» — отдельная строка «MAX: поиск по всей площадке не
   поддерживается», а не ошибка.
2. `stage=queued` (B2-15): «В очереди — дождитесь окончания предыдущего поиска», кнопка «Отменить».
3. Долгий поиск: под прогрессом — «обычно 1–3 минуты», счётчик «найдено пока: N» (из `counts.total`
   во время опроса).

**DoD.** Все три состояния воспроизведены на стенде, скриншоты для презентации.
