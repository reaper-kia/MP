# UI — дизайнер (макеты, дизайн-система, тексты, презентация)

Зона: Figma-файл проекта + `docs/ui/` (экспорт токенов и иконок) + слайды. Код пишет FE — [FE.md](FE.md);
твоя задача — чтобы FE **не придумывал** экраны сам и чтобы интерфейс набрал баллы:

| Критерий | Баллы | Что от тебя |
|---|---|---|
| Удобство: 5 сценариев | 5 × 2 | понятный путь «запрос → период → источники → подборка → выгрузка», все состояния |
| Общий UX и UI | 5 | читаемость, иерархия, контраст, единообразие статусов, работа с подборками разного объёма |
| Ясность презентации | 2 | структура, читаемые слайды |
| Демонстрация | 5 | (с TL) сценарий показа |

Пользователь — сотрудник агентства печати **без технической подготовки**, работает на ноутбуке/ПК
в Chrome (1366×768 и 1920×1080). Мобильная версия не нужна. Регистрации нет.

Данные, которые показываем, и их типы — ниже в каждой задаче. Полный справочник полей —
[`docs/API.md`](../API.md) (раздел «Схемы»), смысл правил — [`docs/ARCHITECTURE.md` §5](../ARCHITECTURE.md).

**Как сдавать.** Каждая задача — фреймы в Figma с именем `UI-0X / Экран / Состояние`, ссылка в чат
FE и TL. Сначала **wireframe** (серые блоки, реальные тексты) → FE начинает верстать → потом визуал.
Не ждём идеала: FE работает от твоих вайрфреймов уже на H+4.

## Старт после pull

Посмотреть, что уже сверстано, можно без бэкенда (нужен Node 22):

```bash
git pull
cd frontend && npm install
npm run dev:mocks          # открыть http://127.0.0.1:5173
```

Сценарии включаются словами в поле запроса: «безопасность» — частичный итог, упавший OK, 3 сюжета, пост
без даты, «начало поста»; «пусто» — ничего не найдено; «ошибка» — поиск не выполнен; вставленный текст
длиннее 300 символов — поиск по тексту новости. Если запускать неудобно — попроси FE прислать скриншоты.

**Что уже есть в интерфейсе (FE-01…FE-05, на стандартных компонентах Mantine, без макетов):** форма
поиска с подсказкой «Понято как», периодом, режимом, площадками и выбором источников; прогресс и «Где
искали»; плашка параметров и баннер «Параметры изменены»; вкладки, фильтры, карточка публикации, сюжеты,
исключение. Нет: экранов состояний итога (FE-06 в работе), выгрузки (FE-07), управления источниками
(FE-08), истории (FE-09), расширения (FE-10). Тема `frontend/src/theme.ts` ждёт твоих токенов
(`docs/ui/tokens.json` ещё нет). Поэтому UI-01 и UI-03 теперь — не «с нуля», а сверка с тем, что
сверстано: список правок вместо нового экрана там, где структура уже годится.

Отметки `[x]` по задачам ниже ставишь сама/сам: результат в Figma, из репозитория его не проверить.

### [ ] UI-01 · P0 · к H+4 · вайрфреймы основного пути
**Цель.** FE верстает с H+4 по твоей структуре, а не по своей фантазии.

Экраны (1440 px ширина, серые блоки, **настоящие тексты** из словаря ниже):
1. **Поиск — пусто** (`/`): форма из FE-03 — поле запроса, период, режим, площадки, источники,
   строка про регион, кнопка «Найти».
2. **Поиск идёт** (`/search/:id`): форма сверху (заполнена), прогресс, блок «Где искали» раскрыт,
   первые результаты появляются.
3. **Подборка готова**: плашка параметров, вкладки, фильтры, список карточек, кнопка «Скачать Excel».
4. **Источники** (`/sources`): таблица + добавление по ссылке с предпросмотром.

Решить и показать: где форма относительно подборки (рекомендация — форма компактно сверху,
сворачивается после запуска в одну строку-плашку с кнопкой «Изменить»), где «Где искали» (над
списком, сворачиваемый), где выгрузка (справа в плашке параметров — всегда на виду).

**DoD.** 4 фрейма, FE подтвердил, что понятно, что верстать.

### [ ] UI-02 · P0 · к H+8 · мини-дизайн-система
Основа — Mantine (FE не будет писать компоненты с нуля), задача — **токены и правила**:
- Цвета: primary, нейтральные, и **семантика статусов**, единая во всём продукте:

  | Смысл | Где встречается | Значения данных |
  |---|---|---|
  | Успех / обработано | цель `done`, поиск `completed` | `TargetStatus.done`, `SearchStatus.completed` |
  | Нейтрально / пусто | цель `empty`, `skipped` | «постов за период нет» |
  | Идёт | `pending`, `running`, `queued` | — |
  | Внимание | поиск `partial`, «Спорно», «Дата недоступна», «Параметры изменены» | — |
  | Ошибка | цель/поиск `failed` | — |
  | Связь: прямая / косвенная / спорная / отсеяно | чип у карточки | `Relevance` = `direct` / `indirect` / `disputed` / `rejected` |
  | Тональность: позитив / нейтр. / негатив | чип у карточки (тихий) | `sentiment` = `positive` / `neutral` / `negative` / `null` (не показываем) |

  Контраст текста ≥ 4.5:1. Статус **никогда не только цветом** — всегда иконка или слово.
- Типографика: 1 шрифт (кириллица! напр. Inter, PT Sans, Golos), шкала 12/14/16/20/24/32, межстрочный.
- Иконки площадок: VK, OK, MAX, «Сайты» — одного размера и стиля (16 и 20 px).
- Отступы 4/8/12/16/24/32, радиусы, тени — сколько нужно, не больше.
- Компоненты-состояния: бейдж статуса, чип связи, бейдж региона, пометка «нет данных».

**Сдать.** Страница «Tokens» в Figma + `docs/ui/tokens.json` (`{ "colors": {...}, "fontFamily": ...,
"radius": ..., "spacing": [...] }`) — FE перенесёт в тему Mantine.

### [ ] UI-03 · P0 · к H+12 · карточка публикации и сюжет
Самый важный компонент: по нему эксперт «оценивает материал по заголовку и выдержке, не открывая
страницу» (сценарий 4).

**Данные карточки** (`Result`) и как их показывать:

| Поле | Тип | Пример | Крайние случаи — нарисовать |
|---|---|---|---|
| `platform` | `"vk" \| "ok" \| "max" \| "news"` | `vk` | все 4 иконки |
| `source.name` | string | «Новости Красноярска» | длинное — до 80 симв. («Администрация Емельяновского района Красноярского края — официально») |
| `source.is_regional` | boolean | `true` | бейдж «Региональный источник» / без него |
| `title` | string | «В Ачинске прошёл рейд «Пешеход»» | до 120 симв.; 2 строки макс. |
| `title_source` | `"title" \| "post_start"` | `post_start` | пометка «начало поста» (заголовка у поста нет) |
| `published_at` | дата-время \| `null` | 15.10.2026, 10:20 | `null` → «Дата недоступна» (заметно, оранжевым, с подсказкой «может быть вне выбранного периода») |
| `excerpt_parts` | `{text, highlight}[]` | фраза с 2 подсвеченными словами | 300 симв., 3 строки + «Показать полностью»; подсветка совпадений |
| `relevance` | `direct \| indirect \| disputed` | `direct` | 3 варианта чипа + `rejected` для вкладки «Отсеяно» |
| `explanation` | string | «Пост о рейде ГИБДД у школ Ачинска» | ~100 симв.; где показывать — подсказка у чипа или строка под выдержкой (реши) |
| `region.evidence` | string \| `null` | «Ачинск» | бейдж «Упоминается: Ачинск»; `null` → нет бейджа |
| `sentiment` | `positive \| neutral \| negative \| null` | `neutral` | тихий чип; `null` → ничего |
| `metrics.*` | число \| `null` | 5 400 просмотров | все `null` → строка метрик не показывается; часть `null` — показываем только известные |
| `url` | string | — | кнопка «Открыть пост» (в новой вкладке) |
| `excluded` | boolean | `false` | чекбокс «Исключить»; вид исключённой карточки (в режиме «Показать исключённые») |
| `group_size` | число | 3 | если > 1 в плоском списке — «ещё 2 размещения» |

**Сюжет** (`ResultGroup`, режим «Группировать одинаковые новости»): `title`, `size` («3 размещения»),
`platforms[]` (иконки), `earliest_published_at`, раскрытие со **всеми** размещениями (у каждого своя
ссылка, источник и дата), действие «Исключить весь сюжет». Подпись: «В счёте каждое размещение —
отдельная публикация» (правило ТЗ).

**Сдать.** Компонент с вариантами (direct/indirect/disputed × с датой/без × с заголовком/начало поста
× региональный/нет × выбрана/исключена), сюжет свёрнутый и раскрытый, плотный вариант для 100+
результатов (можно таблицей — реши, что удобнее для «подборок разного объёма»).

### [ ] UI-04 · P0 · к H+14 · все состояния поиска
По одному фрейму на каждое (FE-06 их реализует 1:1):

| Состояние | Когда | Что на экране |
|---|---|---|
| Идёт: стадии | `stage`: `queued` → `analyzing_query` → `collecting` → `scoring` → `grouping` | текст стадии + прогресс «12 из 30 источников» |
| Где искали | всегда | список целей: площадка · название · статус (`pending/running/done/empty/failed/skipped`) · «получено 120 · в подборке 7» · ошибка · «Повторить»; свёрнутый вид «Обработано 28 из 30 · не удалось: 2» |
| Готово | `completed`, есть результаты | подборка |
| **Ничего не найдено** | `completed`, 0 | спокойный экран: «Подходящие публикации не найдены», где искали, советы — **не путать с ошибкой** (ТЗ требует различать) |
| Частично | `partial` | подборка + жёлтый баннер «Не удалось обработать 2 источника» + «Повторить» |
| Ошибка | `failed` | красный блок с причиной + «Повторить»; найденное раньше остаётся |
| Остановлен | `cancelled` | серый баннер + найденное |
| Параметры изменены | поле формы поменяли после поиска | жёлтый баннер «Ниже — подборка по прежним условиям» + «Найти заново» |
| Нет связи | сеть/сервер | всплывающее уведомление, экран не очищается |
| Подсказка запроса | `query_analysis` / `needs_clarification` | «Понято как: тема — …» / жёлтое «Уточните…» |
| Площадка не подключена | OK / MAX пока отвечают 501 `NOT_IMPLEMENTED`; VK без ключа — 503 `PLATFORM_UNAVAILABLE` «не настроен доступ» | вид чекбокса площадки и строки цели в «Где искали»; **текст** для 501 (сейчас фронт пишет «Сервис временно недоступен», это неверно — FE-12) |
| Упрощённый режим | `warnings[]`: «ML работал в упрощённом режиме» (пока нет модели), «Коллектор в режиме имитации» | серые строки под прогрессом — как не напугать и не спрятать |

### [ ] UI-08 · P0 · к H+40 · презентация

## Реалистичные объёмы данных (для макетов)

- Источников в каталоге: 30–100; в одном поиске целей: 3–60.
- Публикаций в подборке: 0, 5, 25, **300** (нарисовать, как выглядит длинная подборка).
- Отсеяно системой: обычно в 5–20 раз больше, чем в подборке (сотни).
- Текст запроса: от 3 слов до 3 000 символов (вставленная новость) — как выглядит поле с длинным текстом.
- Названия источников: 10–90 символов; заголовки: 30–120; выдержка: до 300.
