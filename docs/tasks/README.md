# Задачи команды — обзор

**`main` теперь собран из всех веток** (сборщик B1 со слоями и VK, поиск B2, eval-наборы ML, фронт
FE-01…05) плюс исправления интеграции. Что работает прямо сейчас: CI зелёный по всем сервисам; стенд
поднимается локально **без Docker** и проходит весь путь пользователя через gateway — площадки →
источник → поиск (по источникам и «везде») → подборка → группы → исключение → XLSX → повтор → отмена,
`make smoke` → `All good`. Данные пока **тестовые** (`COLLECTOR_FAKE=true`), отбор — **эвристики**
(`LLM_PROVIDER=stub`), фронт проверен на моках MSW, `make up` (Docker) не проверялся. Подробно —
[`docs/STATUS.md`](../STATUS.md).

**После pull** каждый идёт в свой файл, раздел «Старт после pull»: там команды именно для твоей роли и
что должно получиться. Общий запуск (Docker / без Docker / Windows) — [README → «Быстрый старт после
pull»](../../README.md#быстрый-старт-после-pull).

## Где смотреть поля, типы и API

| Кому | Справочник (читать) | Первоисточник (править только через TL) |
|---|---|---|
| FE, UI, TL | [`docs/API.md`](../API.md) — все HTTP-ручки, параметры, коды, схемы с типами; [`docs/api-types.ts`](../api-types.ts) — TS-типы | `contracts/http/openapi.yaml` |
| B1, B2, ML, TL | [`docs/GRPC.md`](../GRPC.md) — все RPC и сообщения с типами и комментариями | `contracts/*/v1/*.proto` |

Справочники генерируются из контрактов (`make docs`, входит в `make proto`) —
руками не правятся. В каждой задаче нужные ручки/сообщения и поля выписаны прямо в тексте.

## Как читать задачу

```
### [ ] B2-05 · P0 · к H+10 · зависит от: B2-01, B1-02
> Сделано: … / Осталось: …     ← у начатых задач — что уже есть в коде
Цель — зачем (и какой критерий оценки это закрывает)
Сделать — по пунктам
DoD — проверяемые условия «готово»
```

- **P0** — без этого не проходит сценарий ТЗ. Делается первым, нельзя пропускать.
- **P1** — даёт баллы (доп. возможности, UX), делается после P0 своей вехи.
- **P2** — если осталось время до H+38.
- `[x]` ставим, только когда DoD выполнен и проверен запуском, а не «код написан». Частично сделанное —
  `[ ]` с блоком «Сделано / Осталось».
- Взял задачу → пишешь в чат «беру B2-05». Сделал → `make check` зелёный, PR, галочка `[x]` в файле.
- Блокер больше 30 минут → сразу в чат TL. Не сидим молча.

## Общий DoD для любой задачи

1. Работает на стенде: в `make up` (Docker), а пока TL-11 не закрыт — на локальном стенде без Docker
   (README, вариант Б), и `make smoke` зелёный.
2. `make fmt && make check` зелёные (ruff, mypy --strict, pytest); у фронта — `npm run typecheck && npm run build`.
3. Есть хотя бы один тест на основную логику (хэндлеры — на фейках, как в шаблоне).
4. Ошибки — через `ERROR_CODES`, а не `try/except` в servicer/роутере.
5. Логи с `request_id`, без секретов и без полных текстов постов на уровне INFO.
6. Строка в [`docs/STATUS.md`](../STATUS.md) обновлена честно: ✔ — только то, что запускали и видели.
