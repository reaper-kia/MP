# ml_service

Разбор запроса, оценка связи постов с запросом, группировка. Владелец — ML (`docs/tasks/ML.md`).
gRPC: `contracts/ml/v1/ml_service.proto` (справочник — `docs/GRPC.md`). Порт 50055. Своей БД нет.

```
src/ml_service/
  core/              ← чистая логика без gRPC: можно гонять из eval/ и тестов
    models.py        ← QueryAnalysis, Post, PostScore, Span, PostGroup ...
    text.py          ← основы слов, числа с единицами, даты, шинглы
    region.py        ← справочник Красноярского края + места вне края
    excerpt.py       ← выдержка и подсветка (позиции в исходном тексте)
    llm_json.py      ← ответ LLM → JSON → pydantic → один ретрай
    query.py         ← AnalyzeQuery: эвристика (degraded) и LLM
    scoring.py       ← ScorePosts v1: лексика + эмбеддинги + регион → класс по порогам
    same_news.py     ← «та же новость / другое событие»: место, дата, числа, вложенность текста
    judge.py         ← ScorePosts v2: LLM-судья пачками, кэш, бюджет времени
    grouping.py      ← сюжеты: шинглы (копии, сокращения) + эмбеддинги (пересказы)
  providers/         ← LLM и эмбеддинги за Protocol (base.py): stub | ollama | yandex
    fallback.py      ← цепочка «ollama,yandex»: следующий провайдер, если первый не отвечает
    liveness.py      ← быстро понять, что Ollama на ноуте пропала (connect-таймаут, /api/version)
  engine.py          ← MlEngine: выбирает путь, бюджеты, degraded, инварианты контракта
  dependencies.py    ← сборка из настроек + прогрев моделей при старте
  transport/grpc/    ← servicer (proto ⇄ core), mappers, errors, server
  transport/http_health.py ← GET /health (порт 8085): какой провайдер сейчас отвечает
```

## Запуск

```bash
cd services/ml_service && uv sync
uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest -q

# без моделей: эвристики, все ответы degraded=true
GRPC_ADDRESS=127.0.0.1:50055 uv run ml-service

# локальные модели (основной режим)
ollama serve &                       # или: docker compose --profile llm-local up -d ollama
ollama pull qwen2.5:7b-instruct && ollama pull bge-m3
GRPC_ADDRESS=127.0.0.1:50055 LLM_PROVIDER=ollama EMBED_PROVIDER=ollama uv run ml-service
grpcurl -plaintext -d '{"query":"Безопасность дорожного движения в Красноярском крае"}' \
  127.0.0.1:50055 ml.v1.MlService/AnalyzeQuery            # "degraded": false — модель работает
```

В логе старта видно, что подключено: `ML gRPC server listening on … (llm=ollama:qwen2.5:7b-instruct,
judge=…, embeddings=ollama:bge-m3)`, затем «Прогрев LLM: модель отвечает». Модель не скачана или
Ollama не запущена — сервис **всё равно стартует** и отвечает эвристиками (`degraded=true`), в логе
причина, например `HTTP 404: model "qwen2.5:7b-instruct" not found`.

Качество: `uv run --project services/ml_service python eval/run_eval.py --details` (из корня;
с моделями — с теми же `LLM_PROVIDER=ollama EMBED_PROVIDER=ollama`) → `eval/report.md`.

## Как отбираем (для README и защиты)

1. **AnalyzeQuery.** Текст новости (> 300 символов или ≥ 3 предложений) определяется правилом.
   Остальное — LLM: тип (тема / событие / человек), 3–8 коротких поисковых фраз с синонимами
   («ДТП», «ГИБДД», «пешеходный переход» — поиск VK ищет слова буквально), сущности, «главное» и
   «не путать с» («пожарная безопасность» для дорожной). Ответ — строгий JSON → pydantic → один
   ретрай → иначе эвристика.
2. **ScorePosts v1** (каждому посту, быстро): косинус эмбеддингов запроса и поста (bge-m3) + доля
   слов фразы запроса в посте → прямая / косвенная / спорная / нерелевантная по порогам. Регион —
   по справочнику края. Выдержка — окно из 1–3 предложений с наибольшим совпадением, ≤ 300
   символов; ML отдаёт **только позиции**, текст режет search_service.
3. **ScorePosts v2** — LLM-судья: всё, кроме явно далёкого по смыслу и без единого общего слова,
   уходит в модель пачками по 6 постов. Модель возвращает класс, одно предложение объяснения по
   тексту поста и тональность. Не успела в бюджет / ответила мусором — у поста остаётся оценка v1.
   Резкое расхождение (v1 «прямая», модель «мимо») → «спорная»: полнота важнее, человек проверит.
4. **Текст новости.** Копия, сокращение, пересказ → прямая; похожая новость о другом событии →
   нерелевантная с объяснением («другое место (Норильск), другие цифры (2 вместо 3)»). Признаки:
   общие слова, вложенность текста, близость эмбеддингов и **факты** — место, дата, числа с
   единицами. Модель сказала «та же», а факты спорят → «спорная».
5. **GroupPosts.** Почти дубли — по шинглам и вложенности, пересказы — по общим словам и
   эмбеддингам; при расхождении фактов не склеиваем. Каждый пост ровно в одной группе.

## Модели и настройки

| Что | Модель | Зачем |
|---|---|---|
| LLM | `qwen2.5:7b-instruct` (Ollama, `OLLAMA_LLM_MODEL`) | разбор запроса, судья, тональность; хорошо пишет по-русски, держит JSON |
| Судья (опц.) | `OLLAMA_JUDGE_MODEL`, по умолчанию та же | если батч 30 постов не укладывается в 60 с — поставить `qwen2.5:3b-instruct` |
| Эмбеддинги | `bge-m3` (Ollama, `OLLAMA_EMBED_MODEL`) | мультиязычная, сильная на русском; один вектор и для запроса, и для поста |

**Сервер без GPU — Yandex AI Studio** (`LLM_PROVIDER=yandex`, `EMBED_PROVIDER=yandex`,
`providers/yandex.py`):

| Что | Модель | Зачем |
|---|---|---|
| LLM и судья | `yandexgpt-lite/latest` (`YC_LLM_MODEL`; судья — `YC_JUDGE_MODEL`, пусто = та же) | то же, что qwen: разбор запроса, судья, тональность; ответ строго JSON (`jsonObject`) |
| Эмбеддинги | `text-search-query/latest` для запроса, `text-search-doc/latest` для поста | асимметричная пара Яндекса для поиска «запрос → документ»; один текст на запрос, параллельно `YC_EMBED_CONCURRENCY` (8), кэш в памяти |

Нужно: `YC_FOLDER_ID` и `YC_API_KEY` — API-ключ сервисного аккаунта с ролью
`ai.languageModels.user` на каталоге. Нет ключа — сервис стартует на эвристиках, причина в логе.
429 и 5xx повторяются (`YC_RETRIES`, 2), остальные ошибки выключают провайдер на
`BREAKER_COOLDOWN_SECONDS` — ответы эвристикой. **Вариант без LLM:** `LLM_PROVIDER=stub`,
`EMBED_PROVIDER=yandex` — отбор по эмбеддингам и словам, без судьи (дешевле и быстрее, объяснения
шаблонные).

**Пороги косинуса — у каждого провайдера свои** (`Embedder.thresholds`, `core/similarity.py`):
векторы bge-m3 и Яндекса несравнимы. Ollama (bge-m3) — `SIM_LOW` 0.38, `SIM_HIGH` 0.68,
`SIM_RETELL` 0.86, `SIM_SAME_NEWS` 0.85; Яндекс — `SIM_*_YANDEX` (до калибровки ML-11 те же).
Подобрать для Яндекса: `LLM_PROVIDER=yandex EMBED_PROVIDER=yandex uv run python
../../eval/run_eval.py --details` (печатает косинусы релевантных и нерелевантных постов).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_PROVIDER` | `stub` | `ollama` — локальные модели (ноут с GPU); `yandex` — Yandex AI Studio; цепочка через запятую — `ollama,yandex` (см. ниже); неизвестное имя — ошибка на старте |
| `EMBED_PROVIDER` | пусто | пусто — та же цепочка, что `LLM_PROVIDER`; на сервере `ollama` (Яндекс — после калибровки порогов) |
| `OLLAMA_URL` | `http://localhost:11434` | в Docker: `http://ollama:11434` или `http://host.docker.internal:11434`; на сервере — ноут через туннель `http://host.docker.internal:11435` |
| `OLLAMA_CONNECT_TIMEOUT_SECONDS` | 3 | подключение к Ollama; ноут недоступен — ошибка за секунды, а не за таймаут ответа |
| `OLLAMA_PROBE_AFTER_SECONDS` | 20 | Ollama молчала дольше — перед запросом быстрый `GET /api/version` (0 — не проверять) |
| `HEALTH_ADDRESS` | `0.0.0.0:8085` | HTTP `/health` для нас (пусто — не поднимать) |
| `ANALYZE_BUDGET_SECONDS` / `SCORE_BUDGET_SECONDS` / `GROUP_BUDGET_SECONDS` | 15 / 45 / 40 | бюджеты RPC, меньше таймаутов search_service (20 / 60 / 60 с) |
| `JUDGE_BATCH_SIZE`, `JUDGE_CONCURRENCY` | 6, 2 | постов в промпте и одновременных промптов на один вызов ScorePosts |
| `BREAKER_COOLDOWN_SECONDS` | 30 | после сбоя модель не дёргаем столько секунд — сразу эвристика |
| `SIM_LOW`, `SIM_HIGH`, `SIM_RETELL`, `SIM_SAME_NEWS` | 0.38, 0.68, 0.86, 0.85 | пороги косинуса bge-m3 (Ollama) |
| `SIM_*_YANDEX` | как у bge-m3 | пороги эмбеддингов Яндекса — подобрать по `eval/` (ML-11) |
| Пороги классов | `core/scoring.py` (`DIRECT_AT`…), `core/same_news.py` | подбираются по `eval/` |

Ollama: search_service шлёт до 3 батчей ScorePosts параллельно, каждый — до 2 промптов судьи, то
есть до 6 запросов разом. Если GPU позволяет — `OLLAMA_NUM_PARALLEL=4`; иначе запросы встают в
очередь и часть постов останется с оценкой v1 (это видно в логе: «не успел в бюджет»).

## LLM на ноуте, приложение на сервере (ML-15)

Сервер (2 vCPU, 3.8 ГБ, без GPU) модель не тянет, ноут команды с GPU — тянет. Приложение крутится
на сервере, модели берутся с ноута; ноут выключен или без сети — сервер **сам** переходит на
Yandex AI Studio, нет и его — на эвристики.

```
Ноут (за NAT)                                      Сервер
┌─────────────────────────┐  обратный SSH-туннель  ┌───────────────────────────────────────────┐
│ Ollama 127.0.0.1:11434  │ ─────────────────────▶ │ 172.17.0.1:11435 (адрес docker-моста)     │
│ autossh, systemd --user │  ssh -R 172.17.0.1:    │   ▲ host.docker.internal:11435            │
└─────────────────────────┘  11435:127.0.0.1:11434 │ ml_service  LLM_PROVIDER=ollama,yandex    │
                                                   │   1) Ollama ноута  2) Яндекс  3) эвристики │
                                                   │ search_service ─gRPC─▶ ml_service (как был)│
                                                   └───────────────────────────────────────────┘
```

- **Почему туннель и Ollama, а не gRPC до ноута.** Ноут за NAT — соединение открывает он
  (обратный SSH-туннель, шифрует SSH, порт наружу не открыт: слушает только адрес docker-моста).
  Код ML один — на сервере, деплоится со всем; переключение «ноут → Яндекс → эвристики» — внутри
  `ml_service` (`providers/fallback.py`), без правок search_service и контрактов.
- **LLM** — по запросу: первый доступный провайдер, ошибка — следующий. Упавший провайдер
  `BREAKER_COOLDOWN_SECONDS` (30 с) не дёргаем; через 30 с снова пробуем ноут — вернулся, значит
  снова Ollama.
- **Эмбеддинги** — по вызову: в одном ScorePosts / GroupPosts все векторы от одного провайдера и
  его же пороги. Провайдер упал посреди вызова — весь вызов заново на следующем (или без векторов).
- **Пользователь переключения не видит**: ответ Яндекса — тоже ответ модели, `degraded=false`.
  Нам видно: в логе `ml provider switched: llm ollama:qwen2.5:7b-instruct → yandex:… (причина)` и
  `curl -s localhost:8085/health` на сервере (активный провайдер, доступность, последняя ошибка).
- **Ноут пропал — понять быстро.** Подключение — `OLLAMA_CONNECT_TIMEOUT_SECONDS` (3 с). Но
  «мёртвый» туннель sshd ещё ~30 с держит открытым: соединение принимается и молчит. Поэтому если
  Ollama не отвечала дольше 20 с, перед запросом — `GET /api/version` с таймаутом 3 с; на сервере
  sshd закрывает такую сессию за 30 с (`ClientAliveInterval 10` × 3, роль Ansible `tunnel`).
- **Эвристики** (`stub`) — как раньше: `degraded=true` и предупреждение «ML работал в упрощённом
  режиме». `ML_SHOW_DEGRADED_WARNING=false` (search_service) его прячет — на демо держим `true`:
  критерии требуют отделять работающее от имитации.

Настройка (один раз):

```bash
make llm-tunnel-server       # сервер: ключ туннеля в authorized_keys (только этот -R), sshd, ufw
make llm-tunnel-install      # ноут: autossh + systemd --user, автозапуск и после перезагрузки
make llm-tunnel-status       # юнит, лог, Ollama ноута через туннель, /health ml_service на сервере
make deploy                  # .env сервера: LLM_PROVIDER=ollama,yandex, EMBED_PROVIDER=ollama
```

## Какие данные куда уходят

- **Ollama (ноут с GPU)**: текст запроса и тексты публичных постов уходят только в Ollama на
  ноуте команды — локально или с сервера по SSH-туннелю (шифрует SSH, третьим лицам не уходит).
  Денег не стоит — цена в секундах (`мс/пост` в `eval/report.md`) и в памяти GPU
  (7B ≈ 5 ГБ, bge-m3 ≈ 1.2 ГБ). Локальный стенд и сервер вместе делят одну видеокарту.
- **Yandex AI Studio (сервер)**: текст запроса и тексты публичных постов (до 2000 символов на
  эмбеддинг, до `JUDGE_MAX_POST_CHARS` в промпте судьи) уходят в Foundation Models API Яндекса по
  HTTPS. Оплата — по тарифу Yandex AI Studio за токены генерации и эмбеддингов; расход на один поиск
  считается по `usage` в ответах (B2-11 / ML-11).

Персональных данных пользователя в запросах нет: только публичные публикации и текст запроса.

## Без моделей (фолбэк)

`stub`, все провайдеры цепочки недоступны (ноут выключен и ключа Яндекса нет), модель не
скачана, упала или не уложилась в бюджет → эвристики:
разбор по правилам (тип, сущности, «безопасность» → подсказка уточнить), оценка по совпадению слов,
«та же новость» по фактам, группы по шинглам. Ответы с `degraded=true`, в поиске — предупреждение
«ML работал в упрощённом режиме». Тональность без модели — «не определена» (не выдумываем
«нейтрально»). Сервис не падает ни из-за модели, ни из-за её кривого ответа.

Инварианты ответа `ScorePosts` (проверяются в `engine.py` и тестах): один `PostScore` на пост, тот
же порядок и `id`; span'ы внутри `text`, `start < end`; выдержка ≤ 300 символов; объяснение — одно
предложение ≤ 150 символов; `score` в полосе своего класса (сортировка «класс → score» не ломается).
