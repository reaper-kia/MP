# МедиаПульс — медиамониторинг соцсетей

Кейс финала Первенства России по продуктовому программированию (заказчик — Агентство печати и
массовых коммуникаций Красноярского края). Сотрудник агентства одним полем задаёт тему, событие,
человека или текст новости, выбирает период и источники и получает подборку **реальных** публикаций
VK, Одноклассников, MAX и новостных сайтов края: с прямыми ссылками, дословными выдержками и
объяснением «почему попало». Подборку можно проверить, почистить и выгрузить в XLSX.

**Стенд:** http://109.196.167.204:8080. Регистрация не нужна, ключи площадок уже настроены на
сервере, источники края загружены в каталог.

## Как пользоваться

1. **Источники** (страница «Источники»). Вставьте ссылку на группу VK / OK, канал MAX или сайт —
   система сама покажет название и площадку («Уже в списке», если такой уже есть). Список можно
   загрузить файлом XLSX: ссылка, название, региональный да/нет. Флажок «Активный» — источник
   участвует в режиме «Везде».
2. **Запрос.** Одно поле для темы, события, человека или полного текста новости; тип запроса
   система определяет сама и показывает, как поняла. На расплывчатый запрос («новости») предложит
   уточнить.
3. **Период и режим.** Даты считаются по времени Красноярска. Режимы:
   - **«Мои источники»** — только выбранные вами источники;
   - **«Везде»** — все активные источники каталога на выбранных площадках плюс поиск по всей
     площадке там, где он доступен (сейчас — по RSS-лентам новостных сайтов). Пост без привязки
     к Красноярскому краю (ни по источнику, ни по тексту) в «Везде» отсеивается с объяснением.
4. **Ход поиска.** Видны стадия, прогресс, «Найдено пока» и блок «Где искали»: по каждому источнику —
   сколько получено, сколько попало в подборку и что не удалось. Обычно 1–3 минуты.
5. **Подборка.** Карточка: площадка, источник, дата, заголовок, дословная выдержка с подсветкой,
   ссылка на пост и связь с запросом — прямая / косвенная / спорная — с объяснением одной фразой.
   Копии и пересказы одной новости собраны в сюжеты, но каждое размещение считается отдельно.
   Ничего не нашлось — это «Подходящие публикации не найдены», а не ошибка; недоступные источники
   перечислены отдельно с причиной, «Повторить» перезапускает только их.
6. **Проверка и выгрузка.** Лишнее исключается вручную, счётчики пересчитываются. XLSX (и DOCX)
   содержит ровно то, что на экране: шапка с запросом, периодом и режимом, таблица с кликабельными
   ссылками, лист «Охват».
7. **История** — подборки, собранные в этом браузере. Регистрации нет (по ТЗ), поэтому браузер
   получает случайный анонимный id: чужие поиски в истории не видны. Ссылкой на подборку
   (`/search/<id>`) можно поделиться — по ней она открывается у любого.

**Расширение Chrome / Яндекс Браузера «Проверить пост»** — выделили текст поста на любом сайте →
правая кнопка → «Найти размещения в МедиаПульс» → в окошке заголовки найденного со ссылками.
Ставится без прав администратора (раздел [«Расширение»](#расширение-браузера)).

## Площадки

Подробно — методы, лимиты, тексты ошибок, как проверено: [«Как получаем публикации»](services/collector_service/README.md#как-получаем-публикации-b1-10).

| Площадка | Как получаем | «Мои источники» | «Везде» | Что нужно |
|---|---|---|---|---|
| ВКонтакте | официальный VK API: `groups.getById`, `wall.get` | ✔ | все источники VK из каталога | сервисный ключ VK (есть на стенде) |
| Одноклассники | публичные страницы групп без входа (в API OK нет метода «посты группы») | ✔ | все источники OK из каталога | ничего |
| MAX | Bot API: сообщения каналов, где наш бот — администратор | код готов, нужен токен бота | — | токен бота (выдаётся только юрлицу или ИП) |
| Новостные сайты | RSS-ленты; анонс → открываем статью | ✔ | источники каталога + свежие ленты сайтов из перечня | ничего |

**Почему «Везде» — это каталог, а не поиск по всей площадке.** Поиск VK (`newsfeed.search`) закрыт
для ключей приложений (ошибка 1051, проверено 19.10 и сервисным ключом, и токеном VK ID); у OK и
MAX открытого поиска нет вовсе. Остаётся платный Yandex Search API (`site:vk.com`, `site:ok.ru`) —
код для него есть и включается одним ключом (`YC_SEARCH_API_KEY`), но на стенде он не подключён.
Поэтому «Везде» читает все активные источники каталога края; каталог пополняется на странице
«Источники» или файлом.

Достоверность: ссылка, текст, дата и название источника берутся только из ответа площадки; пост не
открылся — в подборку не идёт; нет даты — «дата недоступна», а не «в периоде». Лимиты сбора: до 150
постов с источника, до 200 на поиск по площадке, 50 секунд на источник — не успели, отдаём собранное
с пометкой «частично».

## Как отбираем и считаем

- **По смыслу, а не по словам.** ML разбирает запрос (тип, поисковые фразы, сущности), затем каждый
  пост получает связь — прямая / косвенная / спорная / не связана — с объяснением и положением
  выдержки. Эмбеддинги `bge-m3` отсекают явно далёкое, LLM `qwen2.5:7b-instruct` судит остальное.
  «Пожарная безопасность» не попадёт в подборку по «безопасности дорожного движения».
- **Та же новость.** Для вставленного текста новости копия, сокращение и пересказ — прямые; похожая
  новость о другом событии отсеивается с объяснением («другое место (Норильск), другие цифры»).
- **Регион.** Пост относится к краю, если источник помечен региональным **или** в тексте есть
  привязка к краю (города, районы). В «Везде» пост без обоих признаков отсеивается; в «Моих
  источниках» регион информационный.
- **Без двойного учёта.** Публикация = «площадка + источник + id поста»: найденная дважды (другая
  фраза, повтор поиска) — одна запись. Один текст в трёх группах — три размещения.
- **Тональность** — положительная / нейтральная / отрицательная, видна на карточке публикации.

## Кэш

Поиск с моделью идёт минуты и нагружает VK и OK, поэтому повторы берутся из Redis.

| Что | Где | Сколько живёт | Ключ |
|---|---|---|---|
| Готовая подборка | search_service | 30 мин (`CACHE_SEARCH_TTL_SECONDS`) | основы слов запроса (без порядка, предлогов, окончаний, «#»), период, режим, площадки / источники |
| Посты источника, поиск по площадке | collector_service | 10 мин (`CACHE_COLLECT_TTL_SECONDS`) | площадка + источник + период (или фразы + период) |
| Карточка источника по ссылке | collector_service | 10 мин (`CACHE_RESOLVE_TTL_SECONDS`) | ссылка |

- **Тот же поиск** (сайт или расширение) в течение 30 минут — подборка сразу: это копия готового
  поиска с новым id, исключения одного пользователя к другому не переезжают. В полосе параметров —
  «Подборка из кэша · собрана N мин назад · Обновить»; «Обновить» запускает настоящий поиск
  (`fresh=true`). Другой период, источник или площадка — настоящий поиск.
- **Похожая формулировка** — тот же ключ: «ДТП в Красноярске», «красноярск, дтп» и «#ДТП #Красноярск»
  берут одну подборку. «Не» и «без» меняют смысл и остаются в ключе.
- **Такой же поиск ещё идёт** — повтор не запускает второй сбор с моделью: он ждёт вне очереди с
  пометкой «Такой же поиск уже идёт…» и после финала оригинала получает копию его подборки под своим
  id (в логе `cache join`). Оригинал упал или отменён — повтор ищет сам. Отметка — `mp:search:running:*`,
  живёт не дольше 20 минут.
- **Похожий поиск** по тем же источникам в течение 10 минут — стены групп заново не выкачиваются,
  в логе collector `cache hit`. Оценки ML не кэшируются: другой запрос — другая оценка.
- В кэш попадают только завершённые поиски (`completed`, `partial`) и только полный сбор: ошибка
  площадки или сбор, оборванный по времени, не кэшируются.
- **Redis упал** — поиск работает без кэша, в логах `WARNING cache unavailable`; `/health/ready`
  показывает `"redis": "up" | "down" | "off"`, но готовность не валит.
- **Выключить:** `CACHE_ENABLED=false` в `.env`, затем `docker compose up -d search_service collector_service`.
  Так же применяется смена TTL. **Сбросить:** `make cache-flush`. Память Redis — не больше
  `REDIS_MAXMEMORY` (256 МБ), лишнее вытесняется, на диск ничего не пишется.

## Модели

| Что | Где работает | Когда используется |
|---|---|---|
| Ollama: `qwen2.5:7b-instruct` + `bge-m3` | ноутбук команды с GPU | основной режим, и локально, и для стенда |
| Yandex AI Studio: YandexGPT Lite (`YC_API_KEY`) | облако Яндекса | запасной провайдер; код и тесты есть, на стенде ключа нет |
| Эвристики `ml_service` | везде | если ни одна модель не ответила: поиск работает, но слабее, с предупреждением «ML работал в упрощённом режиме» |

У сервера стенда нет видеокарты (2 vCPU, 3.8 ГБ), поэтому модели он берёт с ноутбука команды
через обратный SSH-туннель:

```
ноутбук: Ollama :11434 ──SSH -R (autossh)──▶ сервер 172.17.0.1:11435 ──▶ ml_service
                                             LLM_PROVIDER=ollama,yandex → ноут → Яндекс → эвристики
```

- **Что уходит наружу:** текст запроса и тексты публичных постов — на ноутбук команды, шифрует SSH,
  порт наружу не открыт. Персональных данных пользователей в запросах нет.
- **Ноутбук выключен** — сервер за секунды это замечает и отвечает эвристиками с предупреждением;
  ноутбук вернулся — через ~1 минуту снова модели. Пользователь ничего не настраивает.
- Какой провайдер отвечает сейчас: на сервере `curl -s localhost:8085/health`. Настройка туннеля —
  `make llm-tunnel-server` и `make llm-tunnel-install`, подробно — [ML README](services/ml_service/README.md).

Качество: размеченные наборы — 102 поста по 4 сценариям (`eval/datasets`, тексты придуманные);
на эвристиках recall 69 %, precision 91 % (`eval/report_baseline_heuristic.md`), слабое место
эвристик — «тема» (recall 24 %). Прогон с моделями на машине с Ollama:
`LLM_PROVIDER=ollama EMBED_PROVIDER=ollama uv run --project services/ml_service python eval/run_eval.py --details`.

## Архитектура

```
Браузер / расширение ──HTTP──▶ frontend (nginx) ──▶ gateway (FastAPI :8000)
                                                       │ gRPC
           ┌───────────────────────────────────────────┼─────────────────────┐
           ▼                                           ▼                     ▼
search_service :50053 ──gRPC──▶ collector_service :50054        ml_service :50055 ──▶ Ollama / Яндекс
источники, поиски, подборка,    VK / OK / MAX / сайты            разбор запроса, отбор,
учёт, экспорт ──▶ Postgres      (без БД)                         сюжеты (без БД)
           └──────────────────────────gRPC──────────────────────────────────▲
```

| Сервис | Что внутри |
|---|---|
| `gateway` | HTTP по `openapi.yaml`, ошибки → понятные коды; `/platforms` → collector, `/query/analyze` → ml, остальное → search |
| `search_service` | каталог источников, поиски, фоновый пайплайн (разбор → сбор → отбор → сюжеты), учёт без дублей, XLSX / DOCX, импорт; Postgres |
| `collector_service` | коннекторы площадок и общие гарантии: период, дубли, лимиты, достоверность; без БД |
| `ml_service` | `core/` — чистая логика отбора и эвристики; провайдеры Ollama / Yandex / цепочка; без БД |
| `frontend` | React 19 + Vite 7 + Mantine 9 + react-query; расширение — `frontend/extension` |

Получение, отбор, хранение и интерфейс разделены; контракты между ними — `contracts/` (proto и
OpenAPI), код из них генерируется и проверяется в CI. Авторизации нет — по ТЗ она не нужна.

## Запуск

### Стенд на сервере (деплой одной командой)

```bash
ANSIBLE_ASK_PASS=True make release   # Ansible: Docker, код, .env, сборка, каталог источников, smoke
```

Сервер, пользователь и порт 8080 — в `infra/ansible/inventory/dev.yml`; ключи площадок берутся из
локального `.env`. Подробно — [`infra/ansible/README.md`](infra/ansible/README.md). Модели для
стенда — туннель с ноутбука (раздел «Модели»).

### Локально в Docker

```bash
make install            # .env из .env.example + зависимости Python
make up                 # фронт http://localhost, Swagger http://localhost:8000/docs
make seed               # каталог источников из seed/sources.xlsx
make smoke              # сквозной сценарий через gateway → «All good»
```

В `.env` из примера `COLLECTOR_FAKE=true` (тестовые посты с пометкой `[FAKE]`) и `LLM_PROVIDER=stub`.
Для настоящих данных: `COLLECTOR_FAKE=false` и `VK_SERVICE_TOKEN`; для моделей — Ollama на хосте
(`OLLAMA_HOST=0.0.0.0`, `ollama pull qwen2.5:7b-instruct && ollama pull bge-m3`) и
`LLM_PROVIDER=ollama`. Если Docker Hub недоступен — зеркало `https://mirror.gcr.io` в
`/etc/docker/daemon.json`.

### Расширение браузера

Сотрудник видит пост в VK (или на любом сайте) и хочет узнать, где ещё это опубликовали, не открывая
сервис: выделяет текст → правая кнопка → **«Найти размещения в МедиаПульс»** (или клик по значку —
выделенный текст уже в поле) → в окошке ход поиска, затем заголовки найденного; клик раскрывает
выдержку, источник, дату, связь с запросом и ссылку на пост. Внизу — «Открыть подборку на сайте»
(тот же поиск, `/search/{id}`) и «Открыть МедиаПульс». На странице группы VK / OK / канала MAX в
окошке есть кнопка «Добавить эту страницу в источники».

**Установка** (права администратора не нужны): распаковать `docs/demo/mediapulse-extension.zip`
(собран с адресом стенда) или собрать самому (ниже).

- **Chrome:** `chrome://extensions` → «Режим разработчика» (справа сверху) → «Загрузить
  распакованное» → распакованная папка → закрепить значок МедиаПульс (пазл → булавка).
- **Яндекс Браузер:** `browser://extensions` (или «Настройки → Дополнения») → режим разработчика →
  «Загрузить распакованное расширение» → папка.

**Как работает.** Поиск идёт в фоне (service worker): окошко можно закрыть посреди поиска — откроете
снова и увидите ход или результат; когда готово, на значке появляется число найденного. По умолчанию —
«Мои источники» (активные из каталога), 30 дней, все доступные площадки; в окошке можно выбрать
«Везде» и 7 дней. Тот же поиск повторно в течение 30 минут — сразу из кэша. Адрес сервера, режим и
период — в настройках расширения (правый клик по значку → «Параметры»); адрес проверяется запросом
`/health/ready`, сервер не отвечает — окошко пишет «Нет связи с сервером».

**Ограничения.** Без магазина расширений: ставится через режим разработчика, Chrome может напоминать
об этом при запуске. В окошке — 20 самых близких публикаций, полная подборка — на сайте. Окошко само
открывается после пункта контекстного меню в Chrome 127+, в более старых — смотрите число на значке.
Нужен Chrome 116+.

**Сборка** (из `frontend/`, после `npm install`):

```bash
VITE_API_URL=http://109.196.167.204:8080 npm run build:ext   # → dist-ext/ (без переменной — адрес стенда)
npm run zip:ext                                              # → dist-ext.zip
```

Разработка окошка без установки: `npm run dev` (с `VITE_API_TARGET` на gateway) →
http://localhost:5173/extension/dev.html?selection=текст — `chrome.*` там подменён, поиск настоящий.

| **Нет** | поиск по всей площадке VK / OK (см. «Площадки»); метрики качества на реальных постах |

Ограничения:

- MAX: Bot API читает только каналы, где бот — администратор, а токен бота выдают юрлицу или ИП.
  Агентство как юрлицо получает его на business.max.ru за несколько минут, после этого MAX работает
  без изменений кода (`MAX_BOT_TOKEN`).
- Новостные сайты отдают в RSS только свежие материалы (обычно 1–3 дня), архив не читается.
- Поиск по ~15 источникам с моделями — 1–5 минут. Поиски идут по одному (`SEARCH_MAX_PARALLEL=1`,
  модели на одной видеокарте): следующий ждёт со статусом «в очереди»; тот же поиск повторно — сразу
  из кэша.
- Сюжеты собираются кусками по 500 постов: копии из разных кусков в один сюжет не склеятся.

### Переменные

Compose — `.env.example`, у каждого сервиса свой `services/<сервис>/.env.example`.

| Переменная | Сервис | Что делает |
|---|---|---|
| `COLLECTOR_FAKE` | collector | `true` — тестовые посты `[FAKE]`; на стенде всегда `false` |
| `VK_SERVICE_TOKEN` | collector | сервисный ключ VK |
| `VK_NEWSFEED_SEARCH` | collector | `false` (по умолчанию) — не пробовать закрытый `newsfeed.search` |

| `LLM_PROVIDER`, `EMBED_PROVIDER` | ml | `ollama`, `yandex`, `stub` или цепочка `ollama,yandex`; пусто у эмбеддингов — как у LLM |
| `OLLAMA_URL` | ml | локально `http://host.docker.internal:11434`, на сервере — туннель `:11435` |
| `YC_FOLDER_ID`, `YC_API_KEY` | ml | YandexGPT (необязательно) |
| `ML_SHOW_DEGRADED_WARNING` | search | `true` — предупреждать, что ML работал на эвристиках (на демо не выключать) |
| `SEARCH_MAX_PARALLEL` | search | сколько поисков идёт одновременно, остальные ждут в очереди; по умолчанию 1 |
| `COLLECTOR_MODE`, `ML_MODE` | search | `stub` — офлайн-заглушки соседей, только для разработки |
| `CACHE_ENABLED`, `REDIS_URL` | search, collector | кэш в Redis; `false` — всё как без кэша ([Кэш](#кэш)) |
| `CACHE_SEARCH_TTL_SECONDS` | search | сколько живёт готовая подборка, по умолчанию 1800 |
| `CACHE_COLLECT_TTL_SECONDS`, `CACHE_RESOLVE_TTL_SECONDS` | collector | посты источника / поиск по площадке и карточка источника, по умолчанию 600 |

### Новый RPC

Правка `.proto` / `openapi.yaml` (через TL) → `make proto` → команда/запрос → хэндлер →
регистрация в `dependencies.py` → servicer и маппер → ошибка в `ERROR_CODES` → схема и ручка
gateway → `make fmt && make check`.

### Отладка

- `request_id` — заголовок `X-Request-ID` и `error.request_id`; search передаёт его collector и ml.
- `X-Client-Id` — анонимный id браузера (фронт хранит его в `localStorage`, `mp_client_id`);
  gateway кладёт его в `RequestContext.actor_user_id`, `ListSearches` отдаёт только эти поиски.
- `curl http://127.0.0.1:8000/health/ready` — кто жив; `make logs s=<сервис>`.
- gRPC напрямую (reflection): `grpcurl -plaintext 127.0.0.1:50054 list`.
- На сервере `.env` принадлежит root: `cd /opt/mp && sudo docker compose logs -f --tail=100 <сервис>`.

| Симптом | Что делать |
|---|---|
| `503 SERVICE_UNAVAILABLE` | сервис не запущен: `make ps`, `make logs s=<сервис>` |
| `503 PLATFORM_UNAVAILABLE` «не настроен доступ» | `COLLECTOR_FAKE=false` без `VK_SERVICE_TOKEN` |
| `502 UPSTREAM_ERROR` | исключение не из `ERROR_CODES` — traceback в логах сервиса |
| «ML работал в упрощённом режиме» | модели не отвечают: `ollama ps` на ноутбуке, `make llm-tunnel-status`, `curl localhost:8085/health` на сервере |
| ml_service не видит Ollama на хосте | Ollama слушает только 127.0.0.1: `OLLAMA_HOST=0.0.0.0` в override службы |
| Docker Hub не качается | `"registry-mirrors": ["https://mirror.gcr.io"]` в `/etc/docker/daemon.json` |
